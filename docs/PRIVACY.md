# DEAD//AIR 0.2.0: daemon, MAC, PANIC и RAM

В 0.3.0 добавлены [встроенный адаптер и Academy](ACADEMY.md). Описание ниже сохраняет сведения о функциях 0.2.0; отдельный отключённый адаптер теперь не обязателен при явно выбранном режиме временного отключения.

## Привилегированный daemon

Daemon запускается через polkit по первому запросу привилегированной операции либо кнопкой **SETTINGS → AUTHORIZE DAEMON**. Системная авторизация требуется один раз на рабочую сессию DEAD//AIR. Последующие отчёты airmon-ng, захваты, смена/восстановление MAC и установка предусмотренных зависимостей проходят через этот процесс без нового вызова pkexec.

Пароль не хранится и не подставляется приложением. Это не постоянно включённая root-служба при загрузке ОС: **END SESSION**, PANIC и штатное закрытие завершают daemon. При следующей рабочей сессии или после аварии daemon авторизация понадобится снова. Политики самого NetworkManager и других системных служб приложение не отменяет.

IPC использует Unix-сокет в root-owned каталоге `/run/deadair-broker`, mode 0600, проверку UID через peer credentials и случайный токен экземпляра. Клиент проверяет, что сервер принадлежит root. Разрешены только фиксированные операции установленного helper. Команда shell, путь к программе, произвольный пакет или каталог удаления не принимаются. Число одновременных клиентских операций ограничено. При закрытии управляющего канала daemon перестаёт принимать операции и даёт существующим helper-процессам завершить восстановление. Если GUI аварийно погибает, закрытие каналов запрашивает остановку; при SIGKILL самих helper остаётся recovery-журнал.

Отдельная root-авторизация не запрашивается для shred: удаление собственных файлов выполняется от обычного пользователя. Если уже идёт системная установка, PANIC не убивает пакетный менеджер посередине транзакции: по таймауту показывает незавершённость и предлагает повторить после её окончания.

## MAC-профили

**ADAPTERS → MAC SPOOFING**:

| Профиль | Префикс |
|---|---|
| Random private address | Случайный локально администрируемый unicast MAC |
| iPhone / Apple vendor prefix | F0:D1:A9 |
| Android / Samsung vendor prefix | 28:83:35 |
| Laptop / Intel vendor prefix | 3C:6A:A7 |
| Raspberry Pi vendor prefix | B8:27:EB |

Оставшиеся байты генерируются случайно. Названия обозначают **только vendor-префиксы**, а не гарантированную модель устройства. Android не имеет единого производителя или OUI. Профиль не меняет ОС, DHCP fingerprint, IP/TCP stack или возможности радиочипа и не обходит проверки доступа сети. Для приватности обычно разумнее случайный локальный адрес, чем vendor-префикс. Соответствие префиксов проверено по [реестру Nmap, сформированному из IEEE](https://raw.githubusercontent.com/nmap/nmap/master/nmap-mac-prefixes).

Смена выполняется настоящим `ip link set … address …` только на отключённом managed Wi-Fi-адаптере. Подключённый интерфейс и занятый физический radio отклоняются. Перед изменением записывается root-only журнал в `/run/deadair/*.mac`; сохраняются индекс интерфейса, phy, исходный MAC и состояние NetworkManager/link. Helper остаётся активным до восстановления, поэтому при обычном RESTORE не нужен повторный пароль. На экране показаны исходный, назначенный и фактически прочитанный MAC. NetworkManager может заменить адрес при последующих соединениях; интерфейс показывает несовпадение, а не утверждает, что профиль всё ещё действует.

При END SESSION, PANIC или закрытии сначала останавливается захват, затем восстанавливается MAC. При смене идентичности устройства или активном соединении восстановление отказывается вмешиваться и оставляет ошибку. После аварии используйте **RESTORE STALE MAC**. Неизвестные устройства и чужие recovery-записи не удаляются автоматически.

Положительная аппаратная проверка назначения/возврата MAC ещё нужна: в тестовом контейнере нет физического Wi-Fi-адаптера. Проверены генерация профилей, IPC, отказ на отсутствующем адаптере и Linux compilation.

## PANIC

В верхней панели есть **PANIC · ERASE & EXIT**. По умолчанию он удаляет **все собственные сессии DEAD//AIR, включая постоянные**, с предварительным вызовом GNU shred. В SETTINGS можно выбрать только текущую сессию и отключить перезапись.

Последовательность: запрет новых задач → отмена discovery в приложении → остановка capture/Hashcat → восстановление MAC → очистка буферов → проверка выбранных каталогов → перезапись/удаление файлов → завершение daemon → выход. При ошибке показывается **CLEANUP INCOMPLETE**, доступен повтор и переход к восстановлению. Ранее запрошенное сканирование NetworkManager может закончиться на стороне ОС.

Удаление ограничено каталогами UUID-сессий внутри собственных disk/tmpfs roots. Проверяются manifest, владелец, тип файла, ссылки и locks. Перед изменением выполняется предварительная проверка всех выбранных сессий. Неизвестные файлы, symlink/hardlink и сессия другого работающего экземпляра вызывают отказ. Shred получает открытый дескриптор проверенного файла, а не путь из GUI. Используется один случайный проход и завершающий нулевой проход; затем файл удаляется. Manifest и lock удаляются после данных, чтобы при ошибке оставалась информация для восстановления. Ошибка во время удаления может оставить частично очищенную сессию — атомарность перезаписи файлов не обещается.

Внешний исходный словарь, отдельно скопированный экспорт, системные журналы, дампы, снимки и чужие каталоги не затрагиваются. Стирание SSD-ячеек не реализовано. `shred` не гарантирует невосстановимость на SSD, CoW/journaled файловых системах и при наличии копий. Это не обещание «отсутствия следов» и не эквивалент Tails.

### Клавиша

По умолчанию: **Ctrl + Shift + F12**. В поле **SETTINGS → PANIC shortcut** нажмите нужную клавишу/комбинацию. Поддерживается и одиночная клавиша; она имеет приоритет над навигацией, работает даже при фокусе в поле ввода и игнорирует автоповтор. Во время записи сочетания PANIC не срабатывает.

Это **сочетание внутри приложения в фокусе**, не глобальный перехват клавиатуры ОС. Зарезервированные системой комбинации могут не доставляться приложению. Настройки живут в памяти; после перезапуска возвращается безопасная стандартная комбинация. В DEMO и браузере PANIC явно показывает preview и не вызывает нативное удаление.

## RAM SESSION / TMPFS

Выберите этот режим до START SESSION. Каталоги сессии, JSON/PCAPNG exports и рабочие файлы/кеши Hashcat создаются в `$XDG_RUNTIME_DIR/deadair-sessions`. Backend проверяет владельца, приватные права и тип файловой системы tmpfs. Если условия не выполнены, операция завершается ошибкой — **дисковый fallback отсутствует**. END SESSION очищает RAM-сессию как временную; PANIC включает её в выбранный scope.

Обычный MEMORY ONLY остаётся режимом без каталога сессии и без файловых заданий Hashcat. RAM SESSION разрешает файловые операции, но направляет их в tmpfs. В 0.2.0 нативное окно также запускается с `incognito: true`, чтобы WebKit использовал эфемерное хранилище.

ОС может выгружать tmpfs и память процессов в swap, создавать hibernation image/crash dumps и вести свои логи. Приложение не отключает это глобально. Вынуть флешку с бинарником — не сигнал корректной остановки приложения; автоматического USB-trigger или гарантии очистки при отключении питания нет.

## Проверки 0.2.0

- TypeScript/Vite production build и 12 модульных frontend-тестов.
- Браузерные IPC contract tests: новая привязка PANIC, scope/shred flags, очистка полей, ошибка/повтор, явно обозначенный preview и выбор MAC-профиля; отдельные прежние проверки черепа/установки.
- Rust: генерация адресов, denylist команд broker, настоящий GNU shred, current/all scope, защита внешних файлов, symlink/locks, RAM storage, защита capture-журнала от коллизии UUID; также прежние parser/storage/D-Bus тесты.
- `scripts/verify-broker.py`: настоящий root-daemon в контейнере; два реальных airmon-ng report через один PID, отказ другому UID/токену и произвольному пакету, отказ отсутствующему адаптеру, удаление сокета после закрытия канала. Это тест после авторизации; системный polkit-dialog с вводом пароля на обычном desktop ещё требует проверки.
