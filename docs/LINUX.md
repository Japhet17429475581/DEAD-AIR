# Сборка, установка и проверка в Linux

В 0.3.0 доступны [Academy, пассивные PMKID-наблюдения и использование встроенной карты](ACADEMY.md). Для выбранной подключённой карты можно явно разрешить временное отключение; затем приложение восстанавливает её профиль. Аппаратная проверка этих переходов остаётся обязательной перед рабочим аудитом.

В 0.2.0 доступен привилегированный daemon с одной авторизацией на рабочую сессию, MAC-профили и PANIC. См. [инструкцию обновления](PRIVACY.md). Автоустановщик также проверяет ethtool, pciutils, usbutils, kmod и coreutils — они нужны для реального airmon-ng и shred.

## Установка готового приложения

Откройте `.deb` в установщике пакетов Ubuntu/Debian либо `.rpm` в менеджере программ Fedora. Затем запустите **DEAD AIR** из меню приложений, обычным пользователем. Пакет содержит GUI, helper и polkit policy. На Arch используйте локальный пакет `.pkg.tar.zst`, собранный по инструкции ниже; поддержка этого рецепта ещё не проверена на Arch.

При первом запуске приложение само определяет недостающие инструменты. **INSTALL DEPENDENCIES** запускает пакетный менеджер после системного запроса пароля администратора. Вводить команды установки зависимостей в терминал не требуется. Перед запуском показаны пакеты; Hashcat можно исключить. Настройка доступна повторно в **SETTINGS → INSTALL MISSING TOOLS**.

Потребуются работающие системные D-Bus, NetworkManager и агент авторизации polkit в графической сессии. Установка пакета NetworkManager не гарантирует запуск службы при нестандартной конфигурации системы. Ошибка службы отображается отдельно от наличия бинарника. Headless-контейнер без polkit-agent не заменяет проверку системного диалога авторизации.

| Система | Пакетный менеджер | Беспроводные инструменты | Необязательный CPU OpenCL |
|---|---|---|---|
| Ubuntu / Debian | apt-get | network-manager, iw, iproute2, aircrack-ng | pocl-opencl-icd, clinfo |
| Fedora | dnf | NetworkManager-wifi, iw, iproute, aircrack-ng | pocl, clinfo |
| Arch | pacman | networkmanager, iw, iproute2, aircrack-ng | pocl, clinfo |

Во всех случаях используется пакет `hashcat`. GPU-драйверы и словари не скачиваются. CPU runtime устанавливается отдельно кнопкой **INSTALL CPU RUNTIME** в Hashcat Lab. Установка использует настроенные системные репозитории; отсутствие пакета, блокировка пакетного менеджера или ошибка сети остаются ошибками. На Arch сначала поддерживайте актуальное согласованное состояние системы: приложение не запускает обновление всей ОС.

## Сборка из исходников

Нужен полноценный Linux desktop. Базовая среда проведённой проверки — Debian 12 x86_64 с WebKitGTK 4.1. Исходная сборка предусматривает Ubuntu 22.04+, Debian 12+, Fedora с `webkit2gtk4.1-devel` и Arch. Сборка в более новой системе может потребовать более новую glibc на машине назначения; совместимость готового Debian-бинарника со всеми дистрибутивами не заявляется.

Одинаковая последовательность для четырёх систем:

```sh
bash scripts/bootstrap.sh --dry-run
bash scripts/bootstrap.sh
bash scripts/package.sh
```

`bootstrap.sh` показывает список сборочных пакетов и запрашивает согласие. Устанавливает недостающий Rust с официального HTTPS-адреса с проверкой SHA-256; при необходимости скачивает Node 22 в `.tools/node` с проверкой контрольной суммы, затем выполняет `npm ci` и `cargo fetch --locked`. Это подготовка **разработчика**, не обязательные действия пользователя готового пакета.

`package.sh` создаёт DEB/RPM с helper/policy. На Arch вызывает `makepkg` с локальными артефактами, без скачивания чужих бинарников. Результаты — `src-tauri/target/release/bundle/`, либо `$CARGO_TARGET_DIR/release/bundle/` при явно заданном target dir. Arch-рецепт находится в `packaging/arch/PKGBUILD` и требует запуска обычным пользователем.

Для разработки:

```sh
bash scripts/dev.sh
```

Для вызовов helper в dev-сборке один раз соберите и установите его:

```sh
cargo build --manifest-path src-tauri/Cargo.toml --locked --release --no-default-features --bin deadair-capture-helper
bash scripts/install-helper.sh
```

При нестандартном target dir передайте путь к helper первым аргументом. Графическое приложение не запускайте через sudo. AppImage сейчас не собирается: установка системного helper требует отдельного пакета.

## Автоматические проверки

```sh
export PATH="$PWD/.tools/node/bin:$PATH"
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features
cargo check --manifest-path src-tauri/Cargo.toml --locked --all-targets
bash scripts/doctor.sh
```

Для браузерных тестов установите Google Chrome, затем `npm run test:e2e`. В CI выполняются сборка, модульные тесты, Rust-тесты и упаковка; аппаратные тесты не подменяются CI.

При наличии Hashcat и реального OpenCL runtime:

```sh
POCL_MAX_PTHREAD_COUNT=4 cargo test --manifest-path src-tauri/Cargo.toml --locked --no-default-features --test hashcat_real -- --ignored --test-threads=1
```

Эти тесты действительно нагружают CPU: бенчмарк SHA-256, известный вектор, отмена и удаление временных данных. GPU/драйверы проверяйте отдельно через **HASHCAT LAB → CHECK DEVICES**.

## Приёмка с реальным Wi-Fi-оборудованием

1. На каждой целевой ОС проверьте первый запуск без Aircrack-ng/Hashcat: список пакетов, системную авторизацию, отмену, успешную установку, повторную проверку. Отдельно проверьте отсутствие сети и занятую блокировку пакетного менеджера.
2. Откройте LIVE-сессию и выполните discovery. Сопоставьте SSID/BSSID/частоты с NetworkManager. Отключите адаптер: должны появиться ошибка или пустой результат, без DEMO-подстановки.
3. Для наблюдения используйте собственную лабораторную AP, согласованный клиент и отдельный отключённый адаптер с monitor mode. Основное подключение не должно измениться. Начните наблюдение выбранного BSSID и вручную подключите свой клиент обычным способом.
4. Сравните фактические кадры и EAPOL-корреляцию с Wireshark. Экспортируйте PCAPNG из дисковой сессии и проверьте формат, BSSID, время, усечение и счётчики. Неполная последовательность не должна отображаться полной.
5. Проверьте STOP, завершение сессии, закрытие окна, отключение USB, SIGTERM и аварийное завершение. После штатного выхода сравните `iw dev` и состояние NetworkManager с исходным. После аварии используйте восстановление из ADAPTERS; при изменившейся идентичности интерфейса ожидайте отказ, а не автоматическое удаление.
6. Проверьте временные и постоянные сессии, перезапуск, экспорт и отказ очистки при неизвестных файлах/ссылках. У временной сессии данные исчезают только после успешной очистки; постоянные сохраняются.
7. Проверьте масштабирование, клавиатуру, reduced motion и отключение аудио на X11/Wayland. Скриншоты из контейнера не подтверждают работу всех графических окружений.
